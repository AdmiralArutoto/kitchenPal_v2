# Figma Translation — KitchenPal

This skill governs how Figma frames become React + Tailwind code in `apps/web/`. The Figma file is Figma Make output: it has no published components, no design variables, frames are full of one-off inline styles. **Interpret the design intent — do not replicate the node tree.**

## When this fires

- Implementing any new component under `apps/web/src/components/`
- Implementing any route page under `apps/web/src/routes/`
- Translating a Figma frame URL into code
- Adding styles to existing frontend code

## Pre-implementation workflow

Follow these steps in order. Do not skip.

### Step 1 — Inventory what exists

Read `apps/web/src/components/index.ts`. This barrel is the canonical list of every shared component in the project. If a frame element resembles something already exported, your default is **reuse + extend**, not new.

Also read `apps/web/src/index.css` to see which design tokens are already defined under `@theme`.

### Step 2 — Locate the Figma frame

Frame URLs are in `figma-links.md` at the repo root. The base Figma file URL is recorded in `CLAUDE.md` under Architecture Decisions.

If the frame you need does not yet have a URL recorded in `figma-links.md`, ask the user to add it before proceeding.

### Step 3 — Fetch the frame via Figma MCP

Use the Figma MCP tools available in the session (`get_design_context`, `get_screenshot`, `get_metadata`, etc., depending on what the connected MCP exposes). Capture both:
- The **screenshot** — this is the visual source of truth.
- The **design context** (layout, typography, color values, spacing).

The screenshot wins when context and screenshot disagree (Figma Make often emits stale or duplicated data).

### Step 4 — Decompose the frame

Before writing any code, produce a brief decomposition in your reply to the user:

1. **Visible elements** — list each meaningful UI element (button, card, input, modal, etc.).
2. **Map to existing** — for each element, name the existing component from `index.ts` that should be reused, or write `new: <Name>` with a one-sentence justification.
3. **Token deltas** — list any colors/spacing/typography values from the frame that are **not** already in `@theme`. For each, decide: reuse an existing token if visually equivalent (within a few percent), or add a new token to `index.css`.

This decomposition is the contract. If the user agrees, proceed. If they push back on a "new:" entry, find a way to extend the existing component instead.

## Component reuse contract

- **80%+ structural match** with an existing component → extend it. Add a prop or variant (`size="sm|md|lg"`, `variant="primary|secondary|ghost"`, `as="button|link"`). Never copy-paste a near-duplicate file.
- **<80% match** → new component. File goes in `apps/web/src/components/<PascalCase>.tsx`. Export from `index.ts` in the same commit.
- **Sub-elements always reuse.** A new RecipeModal still uses the existing Button, IconButton, Input, etc. — don't reinvent atoms inside molecules.
- **Page-specific composition** lives in `apps/web/src/routes/<Route>.tsx`. Don't push one-off layouts into `components/`.

## Design token contract

All colors, spacing values, font sizes, and font weights live in `apps/web/src/index.css` under `@theme`:

```css
@import 'tailwindcss';

@theme {
  --color-primary: oklch(...);
  --color-surface: oklch(...);
  --color-text-default: oklch(...);
  --spacing-section: 2rem;
  /* ...etc. */
}
```

Components reference theme tokens via Tailwind utility classes that the theme generates (`bg-primary`, `text-surface`, etc.).

**Hard rules:**
- **No hex literals in JSX.** `text-[#1a2b3c]` is forbidden. If the frame shows a color that isn't in `@theme`, add it to `@theme` first, then use the generated utility.
- **No inline `style={{ ... }}`** for colors/spacing/typography. Tailwind utilities only. (Inline style is acceptable for dynamic computed values like `transform: translateX(${px}px)`.)
- **Tailwind default scale** (`p-4`, `text-lg`, etc.) is preferred over custom `@theme` entries when it matches visually. Only add a custom token when the default scale doesn't cover the value.
- **Use OKLCH for new colors** if you have a choice — Tailwind v4 defaults to OKLCH.

## Handling Figma Make output

The file was generated by Figma Make. Expect:

- **Auto-named nodes** (`Frame 247`, `Group 12`, `Rectangle 99`) — node names are noise, ignore them.
- **Inline styles per element** — colors and spacing appear as raw values on each node, not as styles or variables. Group repeated values into `@theme` tokens; do not propagate the duplication into the code.
- **Redundant wrapper nodes** — a button might be a Frame containing a Frame containing a Text. Implement as `<button>...</button>`; don't replicate the wrapping.
- **No components** — every "card" in the frame is a fresh node tree. Identify the pattern from screenshots, build one React component, reuse.

When the design context contradicts the screenshot, **trust the screenshot.**

## Code conventions

- **Component files:** `apps/web/src/components/<PascalCase>.tsx`. One component per file, default export.
- **Route files:** `apps/web/src/routes/<PascalCase>.tsx`. One page per file.
- **Barrel:** every shared component is re-exported from `apps/web/src/components/index.ts`. Adding a new component without updating the barrel is an incomplete change.
- **Props:** typed inline (`export default function Button({ variant, ...rest }: { variant: 'primary' | 'secondary' } & ComponentProps<'button'>) { ... }`). Pull from `apps/web/src/types/api.ts` when the prop mirrors an API response.
- **Tailwind ordering:** layout → spacing → sizing → color → typography → state. Use Prettier's Tailwind plugin to sort automatically (already configured in root `.prettierrc`).
- **State:** local `useState` until shared, then lift to a context. No new state library for MVP.

## Verification after implementation

- Run `npm run dev`; open the route in a browser and compare visually to the Figma screenshot. The screenshot from Step 3 is the bar.
- Grep for stray hex literals: `Grep -p "#[0-9a-fA-F]{6}" apps/web/src/` should match only `apps/web/src/index.css`. Any match in `components/` or `routes/` is a fix-it.
- `apps/web/src/components/index.ts` exports the new component (if one was added).
- `npm run build -w apps/web` is clean (TypeScript + Vite both pass).

## Anti-patterns (do not do)

- Creating `Button2.tsx` or `ButtonV2.tsx` because the new variant "feels different." Extend `Button.tsx`.
- Copy-pasting a Tailwind class string across three components. Pull the repeated pattern into a component or a token.
- Replicating Figma Make's wrapper nesting in JSX. Implement the semantic structure.
- Hardcoding text strings that vary by user (recipe names, etc.) from a Figma frame's placeholder content — those come from API state.
- Adding a token to `@theme` without checking whether an existing token covers the value within ~5% perceptual difference.
